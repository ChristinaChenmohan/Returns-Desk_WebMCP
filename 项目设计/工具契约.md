WebMCP 工具契约

| 工具 | 类型 | 作用 |
|---|---|---|
| `search_orders` | 只读 | 按订单号、姓名或邮箱查找订单 |
| `get_return_policy` | 只读 | 获取订单商品适用的政策及政策版本 |
| `check_return_eligibility` | 写入 | 确定性判断是否可退，并保存 Case/不可变资格快照 |
| `compare_resolution_options` | 只读 | 比较换货、退款和商店余额 |
| `draft_customer_message` | 只读 | 根据已确认事实生成模板化邮件草稿 |
| `submit_rma_for_approval` | 写入 | 创建待人工批准的 RMA 提案，不执行最终操作 |

搜索最多返回 5 个订单摘要；多结果时让 Agent 或用户选择。
check_return_eligibility 接收 orderId、lineItemId、数量、原因和商品状态，返回 eligibilityCheckId、政策依据和允许方案。
只有状态为 eligible 的有效 eligibilityCheckId 可以用于提交提案；needs_review 必须先在人工 UI 中复核并生成新快照。
compare_resolution_options 必须接收 eligibilityCheckId，避免 Agent 自行修改资格结论。
方案结果包含买家结果、商家估算成本、库存约束和推荐理由。
draft_customer_message 只能引用已有结构化事实；缺信息时返回 missingInformation，不能虚构。
submit_rma_for_approval 只能创建 pending_action，其描述明确声明不会退款、锁库存、发余额、生成标签或发送邮件。
`search_orders`、`get_return_policy`、`compare_resolution_options` 和 `draft_customer_message` 设置 `readOnlyHint: true`；`check_return_eligibility` 与 `submit_rma_for_approval` 设置 `readOnlyHint: false`。
含客户输入、客户备注或外部数据的结果设置 untrustedContentHint: true。
人工资格复核、批准、拒绝、编辑替换和 Reset Demo 均不注册为 WebMCP 工具。
所有工具使用严格的服务端验证、结构化错误码和 AbortSignal。执行取消为尽力而为；幂等、事务与条件更新保证最终正确性。
工具结果保持简短；完整内容同步显示在 Case Workspace。
页面加载时静态注册核心工具，卸载时通过注册用的 AbortController 注销。

典型调用链：
search_orders
    ↓
get_return_policy
    ↓
check_return_eligibility
    ↓
compare_resolution_options
    ↓
draft_customer_message
    ↓
submit_rma_for_approval
    ↓
Human approves in UI

调用链应是推荐路径，不是硬编码工作流：
Agent 已有订单 ID 时可以直接读取政策；
Agent 已有合法 eligibilityCheckId 时可以直接比较方案；
后端通过依赖 ID 保证安全，而不是要求 Agent 永远按六步调用。

最终批准不暴露为 Agent 工具，它只能通过明确的人类 UI 操作执行。

逐工具 JSON Schema、HTTP 路由、错误、生命周期和 UI 同步以《API与WebMCP详细契约》为准。
